## Issues Found and Resolved

### Issue 1: Development Profile Simulator-Only
**Problem:** The `development` profile only supported Simulator builds (`"simulator": true`), preventing physical device testing during development.

**Resolution:** Added new `development-device` profile with:
- `"simulator": false` for physical device builds
- Production Supabase URLs (device can't reach localhost)
- Dev tools enabled for debugging

**File Modified:** `eas.json`

### Issue 2: Localhost URLs for Device Builds
**Problem:** The `development` profile used localhost URLs which don't work on physical devices.

**Resolution:** Kept `development` profile unchanged (appropriate for Simulator + local Supabase). New `development-device` profile uses production Supabase URLs.

**File Modified:** `eas.json`

### Issue 3: API URL Inconsistency in Production
**Problem:** Production EAS environment had `EXPO_PUBLIC_API_BASE_URL` set to `/functions/v1` without the `/api` suffix, while all other environments used `/functions/v1/api`.

**Resolution:**
1. Deleted incorrect env var: `eas env:delete production --variable-name EXPO_PUBLIC_API_BASE_URL --non-interactive`
2. Created correct env var: `eas env:create production --name EXPO_PUBLIC_API_BASE_URL --value "https://ivnstzpolgjzfqduhlvw.supabase.co/functions/v1/api" --visibility plaintext --non-interactive`

**Verification:** Confirmed via `eas env:list --environment production`

### Issue 4: iOS Credentials Not Configured
**Problem:** Apple credentials not set up for device builds.

**Resolution:** This will be resolved interactively during Phase 2 when running the first device build. EAS will prompt for Apple authentication and auto-generate certificates/profiles.

**Action Required:** User must authenticate with Apple ID during first device build.
